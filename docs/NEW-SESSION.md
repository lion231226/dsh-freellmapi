# 新会话引导词

> **用法**：把下面 ` ```text ` 代码块里的内容**整体复制**，粘贴到新会话的第一条消息里。
> **当前用途**：**验收会话** —— 本会话将跑在 dsh-freellmapi 提供的模型上，对插件本身做全面验收。
> **生成时间**：2026-10-15 · 生成时 HEAD `d224a38`（最新发布 tag `v0.7.16`）

---

## A. 验收会话（现在用这个）

```text
【任务】对 dsh-freellmapi 插件做全面验收，并记录所有错误。

【关键前提 —— 先读懂这一条】
你（本会话）就跑在这个插件提供的模型上。这意味着：
- 你可能会表现出一些异常：记不住前文、上下文被压缩、工具调用拿不到结果、
  把工具调用写成一段文字、答非所问、中英文串味、结论前后矛盾。
- 那些**不是你的错**，是**被验收对象的现象**，而且是最有价值的一手证据。
- 一旦出现，**立即停止验收**，按 ACCEPTANCE.md 的「自举失败处理」执行。
  不要在坏的基础上继续 —— 那会让此后每一项记录都不可信。

【工作区】D:\MyProject\研究学习\DSH插件\dsh-freellmapi

【第一步】读判据文件（只读「阶段 0」那一节就够，不要一次读完）：
    docs\ACCEPTANCE.md
  它把验收分成 4 个阶段，每项都写了「怎么做 → 期望什么」。
  **按阶段做，每阶段做完立即落盘。**

【第二步】严格按 ACCEPTANCE.md 的阶段 0 → 1 → 2 → 3 执行。
  阶段 0 是自举检查，**不许跳过**：它决定后面所有记录是否可信。

【落盘】所有发现写进（`_lead/` 是工作台，不进发布包）：
    D:\MyProject\研究学习\DSH插件\_lead\acceptance-<今天日期>.md
  每条问题格式固定，六项都要有：
    时间 / 当时的路由 / 期望 / 实际 / 是否可复现 / 证据
  **实际那一项要原文抄录，不要转述。** 报错码原样保留。
  不知道的写「不知道」，**不要推测**。

【最后】只报告你**实际观察到**的：
- 哪些验收项通过（列编号）
- 哪些没做，以及为什么（缺凭据 / 需要改配置 / 上下文不够）
- 发现的问题编号 + 一句话摘要
**不要**给「整体良好」这类没有判据支撑的总结。没做的就写没做。

【如果本会话本身出问题】
  切回 DeepSeek 模型（不依赖本插件），把 acceptance 文件的内容贴出来，
  并说明「验收未能完成，原因在插件自身」。
  —— 用坏掉的插件「验收通过」才是真正的失败；让它在验收自己的过程中
     先暴露问题，是这个流程设计上的预期结果之一。
```

## B. 继续开发时用这个

> 若本次不是验收，而是继续实现或修缺陷，用下面这段。

```text
【项目】dsh-freellmapi —— DSH 的免费 LLM 自动路由插件
【工作区】D:\MyProject\研究学习\DSH插件\dsh-freellmapi
【仓库】https://github.com/lion231226/dsh-freellmapi （MIT，最新 tag v0.7.16）

【先读这两份，再动手】
1. D:\MyProject\研究学习\DSH插件\.dsh\skills\dsh-freellmapi\SKILL.md
   → 可携带的方法判据（五条不可协商的判据 + 高频失败形态 + 反模式清单）。
     它是 PROJECT-RULES.md 的摘要，**先读它更省上下文**。
2. D:\MyProject\研究学习\DSH插件\dsh-freellmapi\PROJECT-RULES.md
   → 完整操作手册：PDCA 循环、9 条硬规则、教训账本 L1–L24。需要细节时再查。

【这个项目是什么】
一个 DSH LLM 适配器插件：注册 `freellmapi` provider，对外暴露 `auto` 等虚拟路由，
内部按请求复杂度分档、在 18 家免费 provider 之间选择并故障转移。
是 tashfeenahmed/freellmapi（MIT）的衍生作品 —— `NOTICE` 必须随包，不要删。

【第一步动作】
    cd D:\MyProject\研究学习\DSH插件\dsh-freellmapi
    node tools/gate.mjs --online
  先看门的输出，再决定做什么。门是编号的（G1–G10），失败可以引用编号。

【铁律（违反任何一条，产出都不可信）】
- 守卫写完要**把修复撤掉**，确认它真的会红（用 _lead/reverse-injection-lib.mjs）。
- 声明必须有**可复查的证据**（字节 fixture + sha256，或带方法与日期的实测）。
- 「查不到」先怀疑**观测手段**，不先怀疑被测对象。
- 偶发失败**不许重试掩盖**；报口径时写清是「干净运行」。
- 工作笔记写进工作区 `_lead/`，**绝不进发布包**。

【已知未完成项】见 CHANGELOG.md 的 `[Unreleased]` 段：
  `lib/telemetry.js` 已实现并测过（468 项测试全绿），但**尚未接线**。
  接线点：`lib/index.js` 的 `onRoute` 回调；待加 Config 字段 `telemetry` / `telemetryPath`；
  之后让 `tools/pipeline.mjs` 消费该文件。
```

**两条最容易踩的坑**（都花过时间）：

1. **UI 显示旧清单** ⇒ 不是 UI 没同步，是**运行中的进程持有旧模块**，重启即可。
   profile 是 `link:` 安装，磁盘上的代码早就是新的了。
2. **凭据库里存的 key 可能已失效**（例如 OpenRouter 存过一把 `is_management_key: true`
   的管理密钥，它**不能用于推理**，调用会返回 `401 User not found.`）。
   现象是「模型列得出来但一个都用不了」。遇到就先换 key，别先怀疑路由。
