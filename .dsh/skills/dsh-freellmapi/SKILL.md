# dsh-freellmapi

一个 DSH `LlmAdapter` 插件：转录 `tashfeenahmed/freellmapi` 的免费 provider 目录，在 DSH 的 seam 上实现按复杂度分档的路由、健康度冷却与失败转移。

**包目录**：`dsh-freellmapi/`　**工作台**：`_lead/`（gitignore，绝不进发布包）

> 完整操作手册在包内 `PROJECT-RULES.md`（含 24 条教训账本）。本技能是它的**可携带摘要**：下次做同类工作时，先读这里，再读那份。

## 为什么这个项目需要一套特殊纪律

三条特殊性，决定了后面所有判据：

| 特殊性 | 后果 |
|---|---|
| 是**衍生作品**，上游几乎每天推送 | 数据会腐烂：额度、model id、context window、家数都在变。**不能假设上个月抄的数今天还对** |
| 行为**依赖外部网络** | 同版本在不同网络下表现不同。"我这里能用"不是证据。**测量方法本身就是断言的一部分** |
| 活在**没有文档的 DSH 插件契约**里 | "文档没写"≠"不支持"。判断平台支持什么，**读 `app.asar` 的实现**，不要从别的插件推断 |

## 五条不可协商的判据

这五条是 24 次真实失败换来的。**它们与具体插件无关，做任何"需要可信结论"的工程都适用。**

### 1. 守卫必须能被证明会红

写完测试要**把修复撤掉**，确认测试真的失败。**不做这一步的测试是装饰。**

用 `_lead/reverse-injection-lib.mjs`（在副本上注入，仓库字节不动）。它把结论分成五级，**只有 `RED` 算证据**：

| 判级 | 含义 | 应对 |
|---|---|---|
| `RED` | 已应用且守卫变红 | ✅ 有效 |
| `INERT` | **已应用但守卫仍绿** —— 补丁打在了守卫不执行的路径上 | ⚠️ 注入打偏了，不是"部分成功" |
| `NO-OP` / `ANCHOR NOT FOUND` | 锚点失效或字节未变 | 重新锚定 |
| `RESTORE FAILED` | 副本未还原 | 整个分析无效 |

**出现 `INERT` 一律报 `INCONCLUSIVE`，绝不算部分成功。** 真实案例：容量修复报 `1/3`，我一度读成"部分验证成功"，实际是两条注入打在了 `auto` 根本不走的分支上。

**控制组前置**：注入前必须先在**未注入**状态跑一次并 PASS，否则"全红"毫无信息量（曾因副本缺 `node_modules` 导致 4 条"红"全是模块解析报错）。

### 2. 声明必须可复查，否则不是证据

- **免费声明**：判据在 `lib/free.js`（`pricing.prompt === "0" && pricing.completion === "0"`），且每条必须指向**已提交的字节 fixture** + `bodySha256`，可离线复算。`:free` 后缀**不是价格承诺**。
- **实测值**（contextWindow / maxTokens / toolCalling / vision / reasoning 词表）：`source:` 字段必须写清**方法**（哪个端点、什么命令、哪一天）。**判断**（capability/speed）要显式标注为判断，不许伪装成测量。
- **上游署名**是 MIT 法定义务：`NOTICE` 必须随包（G1 断言）。

### 3. 观测手段坏了，先怀疑观测手段

"查不到"**不等于**"不存在"。三个真实案例：

- 会话日志是 **2,598 个拼接的 zstd 帧**，整文件解压只返回头 201 字节 ⇒ "全库 0 命中"是解码器造的假象
- VPN 把**每个**域名解析进 `198.18.0.0/15` fake-IP 池 ⇒ "解析到非公网 IP"恒真、零信息量
- 被截断到 25 行的目录列表 ⇒ 断言一个文件"不存在"，而它存在

**判据**：任何"0 命中 / 不存在 / 全不可达"的结论，必须先用一个**已知含该内容的样本**验证观测手段本身（正对照）。规则 3 的适用面**包括本地观测**。

### 4. 比较必须排除每次变化的字段

**一个永远不会失败的比较，和一个永远不会红的断言是同一种病。**

真实案例：思考强度探针最初比较**整个响应体**，而每个响应都带新的 `id` 与 `created` ⇒ 无论字段是否被读取都报 "DIFFERS"。同一族的另两个：`JSON.parse` 前不 trim（合法响应被报成解析失败）、**解析前就截断**（超长响应被自己截坏）。

**判据**：比"模型生成了什么"，不比"响应长什么样"；解析用的输入不得是被你裁过的。

### 5. 临时失败不是能力缺失

上游 429 / 503 是**未测得**，不是"不支持"。把它写成"模型不支持工具调用"是**自信的错误答案**——探针能给的最坏输出。

同理：`content: null` 不是"看不见图"，可能是你给的 `max_tokens` 太小，reasoning 模型把预算全花在思考上。**真实案例**：视觉探针用 `max_tokens: 32`，把一条能看图的模型误判为"NOT VISION"，差点据此撤掉一个正确的声明。

## 工作流

### [C] 检查 —— 一个命令，一个结论

```bash
node tools/gate.mjs            # 离线（确定性）
node tools/gate.mjs --online   # 加 G7-G10（网络探测）
node tools/gate.mjs --json     # 给机器读
```

| 门 | 查什么 |
|---|---|
| G1 | manifest：零 `dependencies`、schemastery 在 peer+dev、NOTICE 随包、patch 行名 == 包名 |
| G2 | `Config` 是**活的** schemastery schema（缺则 provider 在 UI 里彻底消失**但仍在路由流量**） |
| G3 | 目录条目 `settingsPath === []`、`settingsNs === provider` |
| G4 | 浏览器半侧：只 require react、不碰 `document`、`inject` 是静态数组 |
| G5 | 全量测试 |
| G6 | `client.js` 的 `@generated:client-setup` 块与 `lib/providers.js` 一致 |
| G7（信息性） | 池内每家的**方法感知**可达性（keyless 家**不带**头探、需 key 家**带假头**探） |
| G8（信息性） | 与上游 `Platform` 联合类型对拍。`missing`＝待办，`extra`＝**真缺陷** |
| G9（信息性） | 免费证据是否漂移（对照已提交 fixture） |
| G10（**阻断**） | 每个宣告的 model id 是否真在该上游 `GET /models` 的服务集合里 |

### [A] 发布仪式（顺序固定，不许跳）

```bash
node tools/gate.mjs --online          # 1. 门全绿
# 2. bump package.json + CHANGELOG + 两版 README 的版本标签
node --test "tests/**/*.test.mjs"     # 3. 再跑一次测试
git add -A && git commit -F <msg>     # 4. 提交（写清根因，不写"修复 bug"）
git push origin main && git tag -a vX.Y.Z && git push origin vX.Y.Z
git rev-parse HEAD                    # 5. 核对 HEAD == 远端 == 标签
```

**改工作区代码 = 改已安装代码**（profile 用 `link:` 指向本目录），但**运行中的 DSH 进程持有旧模块** ⇒ **UI 要等重启才更新**。这不是"UI 没同步"，不要为此改 UI 代码。

## 高频失败形态速查

| 现象 | 先查 |
|---|---|
| provider 在路由但 UI 任何地方都不出现 | G2（settings 命名空间）→ G3（目录条目）→ 规则 7 的五步顺序，**不要从 UI 现象反推** |
| UI 清单是旧的 / 死 id 还在 | 进程持有旧模块 ⇒ **重启**；再查 G10 |
| 一个 id"有端点但调不通" | 免费判据两半：**零价**（`lib/free.js`）**且** `endpoints >= 1`；`:free` 后缀不算 |
| 长 Agent 会话反复压缩、上下文失真 | 声明容量 vs 池内最小窗口（`declaredCapacityFor`）；摘要调用永不被钉、自带容量下限 |
| 某字段"发上去了但没效果" | 检查声明与转发是否**同门控**（`forwardReasoningEffort`）——声明与履行必须不可能不一致 |
| 测试偶发红 | 规则 8：**不许重试掩盖**。报口径——"N/N"指**干净运行**，不是确定性 |

## 反模式清单（每次都栽在这些上）

- 把**推断**当结论写进设计文档（必须在文档里分栏写"证据支持"与"推断"）
- 拿"看起来像"的东西当**参照物**（选错参照物 ⇒ 结论错）
- 抽样当全量、把组内差异**折叠**掉（`contextWindow` 最危险的产生方式）
- 用**绝对阈值**去守一个**相对关系**（范畴错误：阈值必然误伤实测值）
- 想写代码前**没确认依赖的机制真的存在**（"我以为 X 能让 Y 生效"必须找到 X 的产物出处）
- 把工作笔记写进**发布包内**（`_lead/` 才是工作台）
- 就地覆写一个将被反复引用的版本（**改前先 tag/commit**）
